# Global98 真机续测（2026-11-04）

> **历史验证记录，非当前安装/待办说明。** 当前版本为[2.0.0](releases/v2.0.0.md)，完整现状见[文档索引](README.md)和[2.0验证矩阵](testing/global200-release.md)。98当时未捕获的双开真实广告和自然公告，后来在v99分别完成；多机型、32位和Native彻底卸载对照等未做项目仍不算通过。 原哈希、输出与失败记录保留，不把后续成功倒填到旧批次。

## 实际部署与边界

沿用手机现有 1.12.6 / code98 与 20261103.6-global-trial；本轮未重装、未重启、未修改运行时代码或 HMA 配置。主用户 GKD 保持单匹配引擎。

## 结果

- 只读复制 LSPosed 数据库：GKD 主用户有 102 条历史作用域；999 无作用域；测试包在两用户均无作用域。
- 可可影视主用户开屏：`clickNode / Verified / WindowChanged`，51 ms。
- 可可影视临时 999 分身：读到 202 个首页节点；未捕获到广告或公告点击，不记为广告跳过通过。测试后删除本轮临时登记。
- 可可影视前、退出后：测试包 user0 / user999 均有点击处理器标记和 GKD `ActionSucceeded / Verified` 记录。
- 用户关闭主用户 GKD 的 LSPosed 开关后：数据库 `modules_state(user0).enabled=0`；冷启动的两用户测试包仍 `Verified`（56 / 59 ms）。
- 同一开关关闭后，可可影视主用户冷启动再次 `clickNode / Verified / WindowChanged`，52 ms。
- 999 的 GKD 模块启用标记仍为 1，但作用域为空；没有把此状态描述为“两用户模块全部关闭”。
- 本轮未复现打开可可影视后其他目标永久失效。此结论仅覆盖上述有界测试，不等于长期稳定性证明。

## 白名单双向切换与进程恢复补测

用户通过实际 GKD 设置界面操作测试包白名单，顺序为加入→移除→再次加入→再次移除；每一阶段均测试 user0 / user999，共 8 项通过。加入阶段策略拒绝、全部 6 次节点采样为 0、无点击；移除阶段具有点击处理器标记及 GKD `Verified`。整个切换周期 GKD PID 为 20801，目标 PID 分别为 12776 / 14126，均保持不变。测试用 CLEAR_TOP 重建 Activity，不是同一 Activity 实例，也未强行停止或重启目标进程。

随后向主 GKD PID 20801 发送 SIGTERM；在未发出启动命令的情况下，约 2.17 秒观测到新 PID 23732，6 秒后仍存活。恢复后 user0 / user999 均再次节点点击 `Verified`。设置、白名单与 HMA 哈希在本次恢复前后完全一致。该结果不区分 Android 服务重启与模块守护各自的贡献，也不代表 force-stop、全新安装或重启测试通过。

证据分别位于 `local-assets/global-20261104-live-policy/live-transition-summary.json`、`local-assets/global-20261104-recovery/recovery-verification.json` 及同目录命令与节点/动作记录。测试包最后已停止。最终只读检查确认：测试包和可可影视均不在 GKD 白名单，未遗留本次测试条目。

## 重启自动开工补测

用户另行同意后重启，并确认只解锁、未手动打开 GKD。只读观察已见主引擎 PID 11852、Root 服务及 `GKDGLOBAL1`。模块守护日志记录第一次启动服务未找到，2 秒退避后的下一次启动成功，并确认稳定进程；采样脚本未在自动启动观察前发出 GKD 启动命令。重启前后 boot ID 不同，配置/白名单/本地与在线快照规则/HMA/模块 payload 哈希均相同。

主用户测试包节点点击 `Verified`（55 ms）。临时 PM 登记的 999 测试包在重启后被 ROM 移除，启动返回 Activity 不存在，因此该项不计通过；未悄悄重新登记冒充重启保留。改用本就存在的米游社分身，确认 user999 下读取 311 个节点，测试后结束进程；仍没有双开广告实际点击证据。正式双开应用不需要克隆 GKD；临时 PM 测试登记与系统正式双开登记的持久性不同。

完整记录在 `local-assets/global-20261104-reboot/verification.json`。需注意采样器导入重置了同名 commands.json，原重启前/重启命令的完整工具输出保留在会话中，不能把最终 commands.json 当成覆盖所有阶段的完整转录。预重启哈希基线、boot 观测和后续测试记录均已保存。

离线再跑：可选 ABI 打包 16 项通过；回滚 helper 16 项通过且 0 次 ADB。回滚测试器已改用唯一临时目录，修复测试重跑时旧目录重名，并非产品代码故障。当前成品仍为同一 v98 实测字节，未重打包或发布。
