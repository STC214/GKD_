# Global99 首次安装修复与验证（2026-11-04）

历史试验版本：APK code99 / 1.12.7；模块 20261104.1-global-trial。此文记录 v99 的实际修复过程，不代表所有广告场景均已通过。

## 修复

1. 安装器原来按行首查询无障碍组件，遗漏 Android 17 `--brief` 输出中的缩进。现按完整包名前缀及单一字段解析，最多查询 5 次；确认组件前不写首次设置标记。
2. Root 授权等待与服务握手分离：先异步获得 Root Shell，再开始服务握手的 8 秒计时。清理非 Root Shell 缓存；仅首次主用户模块设置允许最多 20 次、5 分钟的授权等待。成功后原子写入完成标记；主动关闭 Root 即取消等待，不修改 Root 管理器数据库。
3. 纯净默认无障碍模式中，前台任务出现早于窗口挂载时，原确认流程停止，导致稍后可见的静态“跳过”节点未被查询。现允许在明确窗口切换后的有限预算内重采样缺失窗口，确认重试同样使用该路径。未确认窗口、后台、画中画、覆盖层仍不得点击。

## 备份、恢复与边界

卸载前暂停守护及应用，保存并读取校验内部数据 TAR、外部缓存 TAR、原 APK、设置和权限状态。恢复时按新 UID 映射文件所有者及缓存 GID，恢复 SELinux 上下文；9 份原存储和订阅文件在执行动作前按原哈希校验。Android 可丢弃 ART/GPU 缓存；权限访问历史及原 AppOps UID/package 存储范围不复原，配置模式重新应用。

测试中发现恢复器的 find 参数不兼容、降级触发 ART 缓存清理，已修正并重新执行成功。原配置使用 Shizuku 自动化模式，新 UID 的外部授权由用户重新批准；最终保留此原配置。新默认 Root＋无障碍路线不要求 Shizuku。HMA 配置未修改。

全局 Native SO/DEX 与此前98实测字节完全相同。最后一次窗口修复是在纯净配置上更新 APK 验证，未在最后构建后再次全局卸载；不得将迭代修复描述成一次无中间步骤的首装成功。APK 在提交源码前构建，版本名保留 de8e0b3-dirty，不是 clean-commit 正式发布包。
