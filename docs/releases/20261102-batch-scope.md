# 批量 LSPosed 作用域与运行名单门禁（2026-11-02，试验版）

## 交互

GKD 高级设置新增两个独立入口：批量配置主用户作用域、批量配置双开作用域。使用 libxposed API 102 的批量申请接口，不调用不稳定的 lspctl 开发者命令，不修改框架数据库。普通白名单变化仅改变运行策略，不重新申请作用域。新装应用或新建分身仍可能需要框架追加授权；不会后台循环弹窗。

批量对象是已安装第三方应用，系统核心组件、GKD 自身和内置检测器名单不进入批量请求。框架作用域是固定能力上限，运行时由现有 GKD 白名单、无障碍排除、检测器文件夹及自动执行/Root 开关共同决定是否生效。移入白名单会停止匹配并撤销本模块拥有的连接；移出后可以重新修复，无需重新勾选已经授权的应用。

## Root 与双开

Root 协议升级为 6。应用普通清单在本机受到 HMA 过滤，因此通过已有 APK RootService 执行 Android 原生 cmd package 清单查询，维持 HMA 原配置不变。主用户 GKD 发布统一策略；XSpace 999 Hook 使用经过 UID 0 对端认证的只读短租约通道，不依赖该用户缺失的主用户远程偏好。包名来自真实 socket UID 对应的包，拒绝共享 UID、不在允许清单、已排除、过期及不可达情况。

双开用户仅登记同一 APK 为 LSPosed 模块。一次性、非导出的配置 Activity 用后退出配置进程，不主动启用第二份 Root/自动执行。Root 进程通过原生 cmd activity 启动该入口，避免把 libsu 的非 AMS 应用线程当成普通 Activity 上下文。没有 ViewRoot 的 push/后台进程不启动策略轮询线程。

SukiSU 包保留安装与单用户保活，仍以用户 0 为匹配引擎。已有 XSpace 时可登记同一 APK 到 999；框架授权由用户确认，脚本不静默授予。此版本只验证 owner 0 / XSpace 999，不宣称支持所有用户类型或第三方虚拟容器。
