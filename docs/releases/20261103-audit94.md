# GKD 1.12.2 · 代码审查与生命周期修复

> **历史版本发布说明。** 本文描述当时LSPosed/模块/测试状态，不是当前使用指南；2.0全局Zygisk路线不再要求逐应用作用域，卸载模块保留APK/数据，真实公告已在v99自然触发验证。原发布边界和产物身份不改写。当前请看[2.0发布说明](v2.0.0.md)、[文档索引](../README.md)与[验证矩阵](../testing/global200-release.md)。

正式 Release：versionCode **94**，SukiSU 模块 **20261103.2 / 2026110302**。

## 修复
- 用服务实例和递增会话代替时间戳判断引擎归属；旧服务退出、延迟清理和快速切换不再覆盖新引擎。执行动作前再次检查归属。
- 拒绝异常的未来事件时间戳，避免一个异常事件阻断其他应用；跨用户窗口令牌包含 userId，防止原版与双开混用动作上下文。
- 节点桥接租约同时校验单调时钟和墙钟；串行发布策略，旧 Binder 死亡回调只清理对应实例。Hook 节点操作切回各自窗口线程，观察异常不影响宿主原操作。
- 内置规则迁移改用 AtomicFile、写后校验和严格完成标记；中断后可重试，保留用户修改、关闭和迁移后的删除选择，版本递增防溢出。
- 节点诊断串行、在 IO 线程执行，并限制节点数、队列、子节点和耗时；正确处理并发服务请求的退出顺序。
- 崩溃记录尽力同步保存后交回 Android 原处理器；临时目录使用原子唯一创建。
- SukiSU 始终只保活主用户引擎，忽略旧配置中的非主用户编号；卸载本模块不再卸载 GKD、清数据或移除双开登记。

## 验证与部署
- 两轮修复回归：应用 **186** 项、Selector JVM **18** 项测试通过，均为 0 失败、0 错误。
- **8** 个 Android Shell 模拟场景通过，包括新装、已有双开、无双开、退出登记、安装失败与异常旧用户配置。模拟测试不操作真实应用卸载。
- Android Lint **0 错误、27 条告警**；告警包含依赖版本、未用资源和现有 Root 私有 API。没有为清告警而批量升级依赖。
- Selector JS 生产编译成功；JS 测试任务没有测试源，不计入通过数量。
- 同一发布 APK 实测：主用户可可影视、水印相机、999 用户可可影视均出现 `clickNode / Verified`。动作后验证耗时分别为 52ms、240ms、51ms，不是完整开屏耗时。
- APK 已安装；现有 SukiSU 模块文件已原位更新，内嵌 APK 与发布 APK 字节一致，保留原 config.conf；单一守护进程已重启并校验。
- HMA 配置、GKD 设置和本地订阅保持原样。未使用截图/OCR；测试后目标应用已结束，999 用户没有第二套 GKD 引擎运行。LSPosed 开发者模式和 Hook 调试保持关闭。
- 已执行 APK 93→94→93→94 对照、隔离目录源码补丁应用及回滚；模块实际原文件已备份，但没有在手机上执行模块降级演练或重启整机。
